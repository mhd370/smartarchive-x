## Inventory and association

[pilot/dataset.json](pilot/dataset.json) is a deterministic, timestamp-free inventory. It records original SHA-256, byte size, full-hash document ID, page numbers, RGB dimensions/pixel hashes, decoder versions, pilot split and PENDING GT/reading-order/authorization fields. Byte-identical source files become aliases of one document. Five saved original-image copies match the source page's decoded pixels. Raster files include all frames; PDFs render transiently at explicit RGB 300 DPI using the recorded PyMuPDF version. No original file is modified and no OCR is run.

Pixel hash = SHA-256 of ASCII `RGB:<width>:<height>:` followed by decoded RGB bytes. No EXIF orientation correction or enhancement is applied. Hashes are decoder-policy dependent; document IDs use original bytes rather than decoded pixels. The inventory scans supported files in `data/input/`; unsupported files require an explicit curation decision instead of silent omission. It additionally inventories `results/**/original*` image candidates, not all crops as if they were source documents.

The inventory is a source snapshot, so its GT fields remain PENDING after later review. `inspect` reads the live GT history for current status. `inventory --check` recomputes the deterministic inventory and fails on drift. To revise source membership, create a separately named manifest; the CLI never overwrites an inventory. Existing baseline CSV and Task 002 example remain unchanged.

[pilot/historical_bindings.json](pilot/historical_bindings.json) explicitly maps seven existing predictions: whole-page/region outputs from v1 and v2, and whole-page/region/line outputs from v3. A binding requires document ID, page number, producer layout version, prediction kind and directory. No basename-only or automatic source inference is allowed.

Adapters verify source byte hash, historical `original.png` pixel match, unique page match, directory/report page number, dimensions where recorded, valid boxes, contiguous region/line IDs, right-before-left columns and top-to-bottom lines. v1/v2 region aggregates are checked against ordered region text files. v3 line aggregates are checked against ordered JSON line records, including empty recognized lines. v3 region component text was not saved separately: its aggregate is checked against metadata/order/length, not independently reconstructed. Full-page text's internal reading order is an OCR result to evaluate, not a fact the adapter can certify.

Historical Windows writes used CRLF after counting in-memory LF text. Adapter producer-consistency checks use a temporary CRLF-to-LF view; **raw prediction snapshots remain byte-identical**, and Task 002 strict metrics still count their actual CR/LF code points. This does not change normalization policy. Existing BOM-bearing comparison/quality text is not silently repaired or imported by these seven adapters.

Historical engine version is unknown. Configuration records preserved script defaults as such, not a recovered CLI invocation. Runtime is reported only where available in saved metadata; timings are not comparable end-to-end performance measurements. Source/page pixel checks provide stronger association than filenames, but cannot prove that a prediction was truly generated by its declared engine. Identical page pixels in different declared pages fail as ambiguous and require curation rather than guessing.

## Exact Windows PowerShell workflow

Run from the repository root with the existing Python 3.11 `.venv`. Pilot commands use already installed Pillow for image decoding; PDF inventory also uses already installed PyMuPDF. No new dependency or OCR executable is needed. See the [benchmark guide](ocr_benchmark.md) for a fresh environment's existing dependency versions. Global flags such as `--dataset`, `--root` and `--store` go before the subcommand.

### Inspect the page and current status

```powershell
.\.venv\Scripts\python.exe tools/pilot_ocr.py inventory --check
.\.venv\Scripts\python.exe tools/pilot_ocr.py inspect
$pilot = Get-Content docs/pilot/dataset.json -Raw | ConvertFrom-Json
$documentId = $pilot.documents[0].document_id
Get-FileHash data/input/sample.png -Algorithm SHA256
Invoke-Item data/input/sample.png
```

`Invoke-Item` opens the source for the human reader. This implementation did not launch a GUI automatically. Inspect the original source, not an OCR prediction, while transcribing.

### Add an independently transcribed page

First confirm authorization. Create a separate working file manually and save as UTF-8 **without BOM**. Do not paste OCR output and attest it as an independent transcription. Resolve illegible spans before marking completeness. The commands below are instructions for the human developer; they have not been executed on the real sample.

```powershell
New-Item -ItemType Directory -Path data/ground_truth/manual -Force
New-Item -ItemType File -Path data/ground_truth/manual/sample_p001.txt
notepad data/ground_truth/manual/sample_p001.txt
# Type from the source, preserve logical Arabic/punctuation, then save UTF-8 without BOM.
.\.venv\Scripts\python.exe tools/pilot_ocr.py submit --document $documentId --page 1 --expected-version 0 --text data/ground_truth/manual/sample_p001.txt --transcriber "YOUR_ACTUAL_ID" --reading-order "spanning header, top to bottom" "right column, top to bottom" "left column, top to bottom" --reason "Initial independent transcription" --manual --complete
```

The listed reading order is a candidate for this inspected layout; confirm it manually and describe tables/footnotes if present. `--manual` attests independent manual transcription; `--complete` attests full-page coverage. An incomplete draft can omit `--complete`, but cannot enter review/approval. Empty nonblank references and missing/duplicate reading-order descriptions are errors. A genuinely blank page requires `--blank` and a zero-byte file. Initial `--expected-version` is 0; existing pages require their current version.

### Review, then approve the exact version

A different human must compare the entire frozen transcript with the original and verify the declared order and full coverage. `inspect` prints the snapshot location through submit output/current status. Use the returned `sidecar` to locate `transcript.txt`; an independent reviewer must inspect that frozen file, not just the mutable working copy.

```powershell
.\.venv\Scripts\python.exe tools/pilot_ocr.py review --document $documentId --page 1 --expected-version 1 --reviewer "INDEPENDENT_REVIEWER_ACTUAL_ID" --attest
.\.venv\Scripts\python.exe tools/pilot_ocr.py approve --document $documentId --page 1 --expected-version 1 --reviewer "INDEPENDENT_REVIEWER_ACTUAL_ID" --attest
.\.venv\Scripts\python.exe tools/pilot_ocr.py inspect
```

`--attest` means the human checked the source, reading order and completeness. The approving actor must be the recorded reviewer and differ from the transcriber. No skipped draft-to-approved transition. These local identities/flags are attestations, not authenticated accounts or proof of actual human conduct. Since you are the sole developer, arrange independent review with the supervisor or another authorized person; do not invent a second identity. No real review/approval was performed by this task.

### Run the comparison

```powershell
.\.venv\Scripts\python.exe tools/pilot_ocr.py compare
```

The command imports all seven saved predictions into a new unique `results/pilot/<run_id>/` bundle and invokes the unchanged Task 002 runner in its own exclusive child directory. It does not rerun OCR. Missing GT maps to NOT_EVALUATED; draft/reviewed GT also remains NOT_EVALUATED. Only the latest approved, complete, hash-valid version can score. Strict and normalized results remain separate, with operation counts and coverage. No approaches are automatically ranked, even after approval. Inspect both policies and dataset limitations before making a scientific claim.

### Correct a reviewed/approved transcription

Edit a separate manual working file after comparing with the source. Submit a new revision with the current expected version and correction reason:

```powershell
.\.venv\Scripts\python.exe tools/pilot_ocr.py submit --document $documentId --page 1 --expected-version 1 --text data/ground_truth/manual/sample_p001.txt --transcriber "YOUR_ACTUAL_ID" --reading-order "spanning header, top to bottom" "right column, top to bottom" "left column, top to bottom" --reason "Describe the source-verified correction" --manual --complete
```

This creates version 2 in draft; version 1 text, sidecars and review decisions remain unchanged. Review and approval must run again with `--expected-version 2`. `compare` chooses the newest revision and does not fall back to an older approval. A stale expected version fails. Previously frozen manifests/reports remain reproducible historical evaluations of their pinned reference version; for a current official comparison always prepare a new bundle with `pilot_ocr.py compare`.

## Storage and audit contract

GT lives under ignored `data/ground_truth/pilot/<hash-of-document-ID>/page_001/`:

```text
v000001/
  transcript.txt                # exact independent manual bytes
  gt.json                       # Task 002-compatible draft sidecar
  revision.json                 # version, actor/time/reason, completeness, parent-state hash
  events/
    000001.gt.json               # immutable reviewed sidecar
    000001.event.json            # actor/time, review attestation, previous-state/sidecar hashes
    000002.gt.json               # immutable approved sidecar
    000002.event.json            # approval event/hash chain
v000002/                        # correction starts a new draft
```

`gt-v1` stays unchanged; version history is outside the sidecar so Task 002 validation/metrics remain compatible. Every sidecar carries document/page/source hash, text hash, order, transcriber and review identity/time. `current` verifies history, source/page association, reference hashes, review sequence and immutable sidecar links. Revision IDs and event IDs are contiguous. A per-page exclusive lock prevents concurrent writers; interrupted or incomplete transactions fail clearly and require inspection, never silent repair. There is no automated crash recovery or tamper-proof/authenticated storage.

Each comparison bundle records dataset/bindings, raw prediction snapshots and hashes, evidence paths/hashes, source pixel association, GT version/status/history-state hash, adapter version and validation limitations in `associations.json`. `benchmark.json` feeds unchanged Task 002 reports. Archived raw source/report files are preserved; no OCR text is promoted to reference data.
